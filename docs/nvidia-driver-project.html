ECS-Optimized AMI: NVIDIA Driver Project

A visual guide to how the amazon-ecs-ami repo builds GPU AMIs, how NVIDIA driver versions are selected, and where your intern project fits.

1. Background: what this repo does

amazon-ecs-ami is a Packer recipe that bakes the ECS-optimized AMIs — the EC2 disk images that Amazon ECS container instances boot from. It takes a stock Amazon Linux base image, boots a temporary EC2 instance, runs a sequence of shell scripts to install and configure everything ECS needs (container runtime, ECS agent, and hardware-specific support), sanitizes the machine, and snapshots the result into a new AMI.

ECS itself is a container orchestrator: it schedules containers (grouped as tasks) onto a cluster of instances based on available CPU/memory/GPU. Your project does not touch the scheduler — it lives one layer down, in the host image, specifically the NVIDIA GPU support for the Amazon Linux 2023 build.

2. The problem your project solves

On a GPU instance, two NVIDIA pieces must agree:

  • The kernel driver baked into the AMI (installed by install-nvidia-driver.sh).
  • The CUDA runtime/libraries inside the customer's container, which the customer controls.

NVIDIA drivers are forward-compatible but not backward-compatible in a key sense: a container built against a newer driver major generally won't run on a host with an older driver. So when the AMI's pinned driver major jumps (your 560 → 590 example), customers running containers built against the older major can break. Your project makes driver selection compatibility-aware and adds a manual override.

Current numbers in the repo: the pinned major is nvidia_driver_major_al2023 = "580" (in variables.pkr.hcl), resolving to the full version nvidia_driver_version_al2023 = "580.178.04" (in NVIDIA_DRIVER_VERSION).

Two different "selection" moments — don't conflate them. Boot-time module selection (nvidia-kmod-load.sh) picks which variant (proprietary / open / GRID) based on the hardware's PCI IDs. But the driver version was already locked in earlier, during the build. Your project is about that earlier version choice.

How resolution works today

In the al2023_gpu path of scripts/check-update-security.sh:

  • Reads the pinned major (580) from variables.pkr.hcl.
  • Queries the AL2023 NVIDIA repo for all nvidia-driver-cuda versions within that major.
  • Lists the NVIDIA GRID .run files in the ec2-linux-nvidia-drivers S3 bucket, intersected across regions so it only picks versions available everywhere.
  • Takes the intersection of repo ∧ GRID and picks the highest with sort -V | tail -1.
  • Emits true nvidia:<version> only if that's newer than what's installed.

scripts/check-update.sh then writes the chosen version into the NVIDIA_DRIVER_VERSION file, which Packer ships to the builder, and install-nvidia-driver.sh compiles all three module variants at that one version.
